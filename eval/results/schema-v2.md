# 스키마 v2 (2026-11-19)

round-01(01~05, format 모드)의 "결정 필요" 9건과 "스킬 지시가 불분명해 추측한 지점"을 한 번에 반영한 기록이다. 사용자가 방향을 승인했다. **스크립트만 확인했고 스킬을 실제로 호출하지는 않았다.**

## 무엇이 바뀌었나

| round-01의 지적 | 조치 |
| :- | :- |
| 결정 1. 작성 규칙이 원본에도 걸림 (02, 05) | `role` 도입. `source`는 구조만, `generated`에만 작성 규칙 적용 |
| 결정 2. 원본 분석에 오답 이유·예문·품사를 지어 넣음 (5장 모두) | `source`에서는 `explanation`, `distractor_notes`, 예문이 선택. SKILL.md에 "원본에 없는 것은 지어 넣지 않는다" |
| 결정 3. 빈칸과 빈칸 추론의 경계가 영역 제목에 기댐 | 보기 낱말 수 중앙값으로 나눔(2 이하 / 3 이상). 검증기가 검사 |
| 결정 4. 보기 언어를 담을 곳 없음 | 문항별 `option_language`. `--compare`가 검사 |
| 결정 5. 지문 없이 풀리는 문항이 통과 (01에서 6문항) | 독립 풀이자가 문항마다 "보기만으로 풀리는가", "답이 둘 이상인가"를 답함. 둘 다 재작성 조건 |
| 결정 6. 짝짓기 규약 없음, 규약대로 담으면 답 노출 (04, 05) | `match_left`·`match_right`·기호·인덱스 배열 정답. `vocab_entries` 금지. 표로 출력 |
| 결정 7. irrelevant, word-bank, 지문 안 번호 빈칸 규약 없음 | "유형별 담는 법" 표에 고정. `word_bank` 필드, 묶음 빈칸은 `(문항번호) ____` |
| 결정 8. 정답지 없는 원본 | `answer_key: provided / solved / none`. 없어도 진행 |
| 결정 9. 5지선다 전제 규칙 | 규칙을 "원본 보기 수"로 다시 씀. multi-blank는 "모든 자리가 검사되어야 한다"로 교체 |
| 수준 근거·보기 평균 길이를 적을 필드 없음 | 적지 않음. `--stats`가 계산 |
| `passage_words` 세는 법이 불분명 | 필드 삭제. 스크립트가 영어 낱말만 셈(기호·빈칸·각주 제외) |
| 문제지 틀을 담을 곳 없음 | `sections`(영역 제목·지시문·범위), `group_instruction`. 이름 줄과 배점표는 자동 생성 |
| 각주·굵게 표기법 | `footnote` 필드, 지문 안 `**…**` |
| 요약문·보기 상자가 발문 안에 들어감 | `prompt_text`, `word_bank` |
| 순서·삽입의 주어진 글이 일반 문단으로 나옴 | `given` 필드, 인용 상자로 출력 |
| 삽입·무관한 문장 보기가 `① ①`로 중복 출력 | 위치 기호뿐인 유형은 보기 목록을 찍지 않음 |
| word-bank·짝짓기 정답이 JSON 문자열로 인쇄 | 정답을 배열로 받고 사람이 읽는 형태로 출력 |
| 단어집의 문항 취급, 원본에 없는 예문 열 | `word-list`는 번호·정답 없이 출력. `vocab_columns`로 원본의 열만 |
| 어휘 단어가 지문 출처라는 제약을 적을 곳 없음 | `words_from_passages`. 검증기가 확인(실패가 아닌 주의로 알림) |
| `language`가 발문과 해설 언어를 묶음 (02, 04) | `explanation_language` |
| detail의 일치/불일치 방향 | `polarity`. `--compare`가 검사 |
| B1+를 표현 못 함 | 수준 값에 `A2+`, `B1+`, `B2+` 추가 |
| 발문을 원본에서 가져올지 표준 표에서 가져올지 | format 모드는 원본 그대로. 표준 표는 원본 없는 모드용 |
| 생성물 제목 | 원본과 같게 |
| 문단 수 모순 | "원본을 따른다"로 통일 |
| 오답 범주 규칙을 지킬 수 없는 유형 | 요지·제목·빈칸 추론·추론에만 적용한다고 명시 |
| 해설의 오답 이유에 보기 번호 없음 | 출력할 때 자동으로 붙임. JSON에는 번호를 쓰지 않음 |
| `--compare`가 SKILL.md에 없음, 독립 풀이 방법 없음 | SKILL.md 4단계를 다시 씀. `render_md.py --paper-only` |
| 실행 환경 (python3 고정, 한글 깨짐, `--help` 오류) | 모든 스크립트가 출력을 UTF-8로 고정, `--help` 처리. SKILL.md에 `python` 대체 안내 |
| 순서 조합 보기 때문에 중복률 5.8% (03-5) | `overlap.py`가 기호뿐인 보기를 세지 않음 |
| PDF 표의 칸이 섞일 때 안내 없음 | SKILL.md 1단계에 한 줄 |
| DOCX와 마크다운 출력이 따로 놀 위험 | `export_docx.py`가 `render_md.py`의 블록 목록을 그대로 씀 |

round-01의 실제 실패 다섯 가지(보기만으로 풀림, 절대 표현 오답, 02-7 낱말 맞추기, 03-5 지문 내 사실 불일치, 05-8 검사되지 않는 자리)는 `question-types.md`에 사례로 넣었다.

## 확인한 것

- 새 샘플 두 벌(`eval/samples/`): 한국어 발문 13문항(묶음, 지칭, 요약문, 무관한 문장, 순서, 삽입, 빈칸 추론, 보기 상자, 조합, 단어 빈칸, 뜻풀이 짝짓기, 뜻 쓰기, 단어집)과 영어 발문 5문항((A)(B)(C)(D), 발문 없는 빈칸, 지문 안 번호 빈칸, 유의어 짝짓기, 한국어 해설). 각각 source·generated 쌍.
- 두 벌 모두 단독 검사, `--compare`, 마크다운·DOCX 출력, `--paper-only`, `--stats` 통과. DOCX에서 묶음 지문 1회, `**it**`이 굵은 글씨로 바뀜.
- **실패 주입 24건 모두 검출**: 정답만 긴 보기, 조합의 고정된 자리, 짝짓기에 `vocab_entries`, 보기 상자에 없는 정답, 지문에 없는 위치 기호, `polarity`·`option_language` 누락, 단어 빈칸인데 구 보기, 묶음 지문 불일치, 오답 이유 개수, 뜻풀이에 낱말 자체, 지칭 표시 없음, 영역 범위, `given` 누락, 정답 분포, 비교 6건(보기 표기, 방향, 보기 언어, 단어집 열, 영역 제목, 지문 길이), 원본 역할 2건(작성 규칙 미적용, 정답 없이 통과), 주의 1건.
- `agentskills validate` 통과. SKILL.md 165줄.

## 남긴 것 (이번에 다루지 않음)

- 이름 줄과 배점표는 자동 생성이라 원본 문구와 다를 수 있다. 원본의 보기 배치(04번 Part 2의 보기 표)도 재현하지 않는다.
- `source_level`은 값 하나만 받는다. 원본이 "B1–B2"라고 적은 경우를 그대로 담지 못한다.
- `topic_tags` 겹침 검사는 생성기가 스스로 통과시킬 수 있다. "같은 소재, 다른 내용"의 범위는 내용 충실도 채점(3단계)에서 본다.
- `words_from_passages` 확인은 앞부분 일치라서 불규칙 변화(choose/chose)를 놓친다. 그래서 실패가 아니라 주의로만 알린다.
- 서술형·문법 문항처럼 지원하지 않는 문항이 섞인 문제지의 처리.
