## 사용자에게 묻지 않고 정한 것

틀렸으면 되돌린다.

1. 원본이 없는 모드의 기본값 표: 제목, 해설 언어, 보기 수, 보기 언어(한국어 발문이면 요지·일치·추론은 한국어, 제목·요약문은 영어), 배점 없음, 품사 표기 `n.` `v.`, 정렬.
2. ~~passage 모드에서 빈칸·순서·삽입은 요청했을 때만~~ → **0.2.3에서 고침.** 사용자 확인: "그대로 싣는다"는 올린 지문을 고쳐 쓰지 말라는 뜻이지 빈칸을 막는 뜻이 아니다. 결정 4번을 "올린 지문은 고쳐 쓰지 않는다. 문항에 필요한 가공(빈칸, 밑줄)은 결과물에서 한다"로 다시 적었다. 기본 구성의 요약문을 빈칸으로 바꾼 것은 묻지 않고 정했다(빈칸이 이 스킬의 핵심 유형이라서). 순서·삽입·무관한 문장은 요청했을 때만 내고 묶음 밖에 따로 낸다.
3. 원본이 없고 보기 표기가 (A)(B)면 요약문 빈칸은 (1)(2).
4. `--words-in`이 못 찾은 단어는 실패가 아니라 주의. 불규칙 변화형(sought ← seek)을 가려낼 수 없어서다.
5. 전체 문장 평균 "참고" 줄을 10% 기준으로 읽으라는 안내. 근거는 04 한 건(+11%)뿐이다.
6. 문항별 `level` 규칙을 위 표처럼 줄인 것.

## 확인하지 못한 것

- **스킬 실제 호출.** 스크립트와 샘플로만 확인했다.
- **"다른 내용" 문제는 그대로다.** 쓰는 규칙 두 줄을 더했을 뿐이고, 원본과 사건 순서가 같은 지문을 잡는 검사는 없다. round-03의 02 1~3번 같은 경우가 줄어드는지는 모른다.
- **풀이자가 "칸 밖에 쓰지 말라"를 따르는지.** 따르지 않아도 그 말을 버리게 했지만, 문법 오류를 칸 밖에 적으면 놓친다.
- **every를 뺀 것의 대가.** round-01의 실제 실패 사례에는 every가 들어 있었다(오답에 always·every·"반드시"). 오탐 1건과 맞는 지적 1건을 맞바꾼 셈이다. 주의 한 줄의 문제라 영향은 작다고 보지만 재지 않았다.
- **밑줄이 모든 보기 화면에서 보이는지.** `<u>` 태그를 지우는 마크다운 보기도 있다. VS Code 미리보기와 DOCX에서는 보인다.
- 뜻 쓰기 문항의 번호(원본에 번호가 없던 01의 "13."), 짝짓기 표의 원본 머리글, 배점표 문구는 고치지 않았다. 형식 충실도에 넣지 않기로 한 작은 차이다.
- 단어집의 뜻·품사·수준이 맞는지, 실행마다 같은 단어가 뽑히는지는 여전히 아무것도 재지 않는다.
