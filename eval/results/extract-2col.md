# extract.py 2단 편집 처리 (2026-11-19)

스킬 호출 없이 스크립트만 확인한 기록이다. 생성 품질과는 무관하다.

## 발견

사용자가 만든 05번 문제지(`eval/sources/pdf/05-A2-2col.pdf`, 2단 편집, 가운데 세로 구분선)를 기존 `extract.py`로 추출하니 **왼쪽 단과 오른쪽 단이 줄 단위로 섞였다.** 1번 지문 사이사이에 6번 지문이 끼어들어, 이 텍스트로는 분석 단계가 성립하지 않는다. PLAN.md에 적어 둔 예상 그대로다.

## 조치

`extract.py`가 쪽마다 단 구분을 찾는다.

1. 쪽 가운데(폭의 35~65%)에 높이가 쪽의 절반 이상인 세로 구분선이 있으면 그 선을 기준으로 한다.
2. 없으면 가운데에서 글자가 없는 세로 띠가 쪽 높이의 절반 이상 이어지는 곳을 찾는다.
3. 어느 쪽이든 양쪽에 낱말이 20개 이상 있어야 단으로 본다.
4. 단 구간 위(머리글, 배점표)는 전체 폭으로 먼저 읽고, 왼쪽 단, 오른쪽 단, 단 아래 순서로 읽는다.

감지하면 stderr에 알리고, `--no-columns`로 끌 수 있다.

## 확인

| 입력 | 결과 |
| :- | :- |
| `05-A2-2col.pdf` (구분선 있는 2단) | 머리글·배점표 → 1~5번 → 6~10번 순서로 나옴 |
| 구분선 없는 2단 (합성 PDF, 좌우 줄 높이 어긋남) | 머리글 → 왼쪽 단 → 오른쪽 단 |
| 1단 본문 + 가운데가 빈 2열 표 22행 (합성 PDF) | 2단으로 오인하지 않음. 표의 행이 유지됨 |
| 위 1단 PDF에 `--no-columns` | 기본 실행과 출력 동일 |

## 남은 한계

- **단 안의 표**: 10번 뜻풀이 표처럼 셀이 두 줄로 넘어가면 `A. … its / (가) empty ____ / side`처럼 줄이 엇갈린다. 내용은 다 있고 A~H 순서도 유지되지만 깔끔하지 않다. 분석 단계가 이것을 제대로 읽는지는 실제 호출로 확인해야 한다.
- **굵게·밑줄 소실**: 2번 "굵게 표시한 it"의 굵은 표시가 텍스트에 남지 않는다. 이 지문에는 it이 한 번뿐이라 풀 수 있지만, 여러 번 나오면 대상을 알 수 없다. SKILL.md 1단계에 "대상이 하나로 정해지지 않으면 사용자에게 묻는다"를 넣었다.
- 가운데에 세로 테두리가 있고 쪽 높이의 절반을 넘는 큰 표는 2단으로 오인할 수 있다. 3단 이상은 지원하지 않는다.
- pypdf로 대체 실행될 때는 2단 처리를 하지 않는다.
